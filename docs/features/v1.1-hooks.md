# Hooks 生命周期（v1.1，v1.2 polish）

在 Agent 关键节点（session / turn / message / tool / system 共 11 个事件）挂
「事件 + 条件 + 动作」三要素规则，让格式化、拦截、上下文注入从手动盯变成机器自动做。

## 流水线插桩

```
L1 → hook.pre → L2-L5 → execute → hook.post
```

- `L1` 是 hard-wall（hook.pre 改不掉）
- `tool.pre` 能拦在五层防御之前
- `tool.post` 用 `try/finally` 包整个 pipeline，任何 tool_call 尝试必触发（完整审计）
- hook 失败 fail-open 不阻断 Agent（与权限系统「fail-closed」对称）

## 条件语法

精确 / 反向 / 正则 / glob，逻辑组合 `all` / `any`（二选一）复用权限规则匹配；`if` 省略即无条件。

## 6 种 action

- `shell`（`exit_code` 判 deny）
- `prompt`（3 档 slot：sticky_reminder / stable_system / temp）
- `http`（simpleeval `parse_expr` 决定 deny）
- `sub-agent`（占位，v1.1.1 接通）
- `clear_sticky_reminders` / `clear_stable_system_overrides`（v1.2 control action，各自只清一类 hook 注入状态）

## 执行控制

- `run_once`（全 session 只跑一次）
- `async`（只对 `tool.post` 允许）
- `timeout_seconds`（默认 30）

## v1.2 polish

- `system.compaction` / `system.cancel` 在各自时机可靠 fire（手动 / 自动压缩路径都 fire，取消时 fire 改 dict payload 含 `iteration`）
- TUI `ToolResultCard` 按 `execution_status` 5 色渲染（L1 红 / hook_pre 黄 / L2-L5 橙 / success 绿 / failed 红）

## ToolResult 新字段

`execution_status` / `denied_by` / `denied_hook_id`，`is_error` 由 `__post_init__` 派生；旧调用方式完全兼容。

## 配置 + 校验

- `config.yaml` 顶层 `hooks:` 块（YAML 列表，声明顺序）
- 启动期 `HookRegistry.freeze()` 收集所有错误一次性报（duplicate id / async+tool.pre / stable_system on tool.* 等）
- 审计：`HookAuditLog` 异步 JSONL append + 100 MB 启动期轮转，默认 `<project>/.baozicode/hooks/<session>.audit.jsonl`
- 没有 `hooks:` 块的 v1.0 项目，Agent 走 legacy 路径（v1.0 byte-identical）
