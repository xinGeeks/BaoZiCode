# SubAgent 修复（v1.5）

v1.5 修复 v1.2 SubAgent 的两个 bug，均以独立 OpenSpec 提案落地并归档。

## Bug 1：`tools: []` 显式空工具集合法

**问题**：角色 frontmatter 写 `tools: []` 时，ToolFilter 把它当成「过滤后意外为空」
抛 `ToolFilterEmptyError`，导致内置 `summarizer`（本意就是无工具角色）无法派发。

**修复**（`baozicode/agents/filter.py`）：

- 新增 `_l2_explicit_empty` 状态位，区分两种「空」：
  - `tools: null`（或不写）→ 无 L2 约束，全工具允许
  - `tools: []` → 显式声明「我要空工具集」，**放行空集，不报错**
  - 其它层过滤后意外为空（如 `tools: [Read]` + `tools_deny: [Read]`）→ 配置冲突，才抛 `ToolFilterEmptyError`
- `layer_states` 输出新增 `L2_explicit_empty` 字段
- 内置 `summarizer` 角色 frontmatter 从 `tools-deny: [...]` 改为 `tools: []`，现在可正常派发

## Bug 2：删同步派发路径，`async_=True` 成为唯一路径

**问题**：`SubAgentManager.dispatch(async_=False)` 走 `_dispatch_sync_blocking`，在
running event loop 里返回 `loop.create_task()` 的 Task 对象而不是字符串结果，调用方
拿到 Task 后没人 await → task 永远 pending / 调用方卡死 / `GeneratorExit`。

**修复**（`baozicode/agents/manager.py`）：

- `dispatch(async_=False)` 直接抛 `NotImplementedError`（msg 含 `v1.5` / `async_=True` 指引）
- 删除整个 `_dispatch_sync_blocking` 方法
- `_do_dispatch` 签名删除 `async_` / `timeout_seconds` 参数
- LLM 若在 `task` 工具里显式传 `async: false` → `task_executor` 返回
  `ToolResult(is_error=True)` 反馈，**不静默 fallback**
- 更新 module / dispatch docstring

**理由**：

1. 同步路径生产代码零调用点（grep 验证）—— 是死路径
2. sync 在 running loop 里本身就是 anti-pattern（阻塞主 loop）—— 设计上不该支持
3. TUI 路径（主 Agent 跑在 asyncio loop 里）天然用 async + idle notification；
   CLI 单次调用也是 `asyncio.run` + 轮询 `task.state`

## 测试

- `tests/agents/test_filter_empty_allowed.py`（6 项）—— `tools: []` 放行 / 区别于 `None` / 冲突才报错 / fork 绕过 L2 / 显式空压过 background
- `tests/agents/test_dispatch_async_only.py`（5 项）—— `async_=False` 抛异常 / 无 `_dispatch_sync_blocking` / `task_executor` 返回 error result / `_do_dispatch` 签名无 `async_`
- `tests/test_subagent_smoke.py` —— 端到端派发 + summarizer 可派发 + `async_=False` 抛异常

## 规格影响

`subagent-manager` capability 的「派发 API」Requirement 增补：

- Explicit empty tools allowlist is accepted
- summarizer role becomes dispatchable
- `async_=False` 自 v1.5 起被禁用，`async_=True` 唯一
