# v0.7 → v0.8 迁移指南

v0.8 在 v0.7 的两层上下文压缩之上,新增三套机制:
**项目指令文件 / 会话存档 / 自动记忆**。从 v0.7 升级到 v0.8 不破坏现有
行为 —— 所有新增机制都有 `enabled: true` 默认值,可以通过配置完全关掉。

---

## 一、发生了什么变化

| 维度 | v0.7 | v0.8 |
|------|------|------|
| 上下文压缩 | ✅ Layer 1 + Layer 2 | 不变 |
| 项目指令 | ❌ 单一 `system_prompt` 字段 | ✅ **三层 `BaoZiCode.md` + `@include`** |
| 会话存档 | ❌ 重启即失忆 | ✅ **JSONL 追加写 + `/resume` + `--resume <id>`** |
| 长期记忆 | ❌ 单一 `memory_path` 文件 | ✅ **双层 `user_dir` + `project_dir` + 自动笔记** |
| session_id | uuid4 32 字符 | **YYYYMMDD-HHMMSS-xxxx** 20 字符 |
| CLI flag | `--config` | **+ `--resume` / `--new` / `--no-banner`** |
| Slash 命令 | 13 个 | **+ `/resume` / `/memory` / `/new`** |

---

## 二、三层项目指令文件

v0.8 引入独立文件名 `BaoZiCode.md`,**不再读取**项目里的 `CLAUDE.md`
(留给 Claude Code 自己读这个项目时用)。三层各放一份手写 Markdown,启动
时按优先级拼接:

```
~/.config/baozicode/BaoZiCode.md     ← user_global(用户全局,最低优先级)
<项目>/.baozicode/BaoZiCode.md       ← project_local(项目级,中)
<项目>/BaoZiCode.md                  ← project_root(项目根,最高优先级)
```

> 高优先级排前面让模型优先遵循;启动时按 `user_global → project_local → project_root`
> 顺序拼接,最终 system prompt 顶部看到的是 `project_root` 的内容在最上面。

**`@include` 引用**

任何一层文件里可用 `@include <相对路径>` 引用其他 Markdown,常用于拆
公共片段。规则:
- 深度 ≤ 5(防止死循环 / 巨型 prompt)
- 路径必须在项目目录内(`realpath` 白名单,跨项目引用被拒)
- 环路用 `visited` 集合拦截

**示例**(`<项目>/BaoZiCode.md`):
```markdown
# 项目根 — 优先级最高

@include .baozicode/conventions.md
@include ./stack.md

技术栈:Python 3.12 + Pydantic v2 + pytest。
```

**完全没有文件的降级**

启动扫到三层全无 → 静默跳过,banner 打印一行 `建议创建项目根目录的 BaoZiCode.md`,
不影响 Agent 运行。

## 三、会话存档

v0.7 退出 = 失忆。v0.8 每条消息追加写到 `sessions/<YYYYMMDD-HHMMSS-xxxx>.jsonl`,
重启可续。

### 默认配置

```yaml
sessions:
  enabled: true
  dir: sessions                  # 相对路径 → 拼到 project_root
  retention_days: 30             # 30 天前的 session 启动时自动清掉
```

JSONL 格式(每行一条 Message 序列化):
```json
{"role":"user","blocks":[{"type":"text","text":"hi"}]}
{"role":"assistant","blocks":[{"type":"text","text":"hello"}]}
{"role":"tool","blocks":[{"type":"tool_result","tool_call_id":"abc","content":"..."}]}
```

### 续接方式

**TUI 内**:`/resume` 弹选择器(标题 / 时间 / 消息数),选定后恢复对话。
**CLI 启动时**:
```bash
# 弹选择器(无 flag + 有历史 sessions)
baozicode

# 直接续指定 session
baozicode --resume 20260101-120000-abcd

# 强制开新(忽略历史)
baozicode --new

# 静默启动(不打印 banner)
baozicode --no-banner
```

### session_id 格式变化

v0.7 用 `uuid4().hex` 32 字符,v0.8 改用 `YYYYMMDD-HHMMSS-xxxx` 20 字符
(4 字符随机 hex 防同秒撞车)。**升级时不破坏旧数据** —— 启动时自动把
`.baozicode/context/<32-char-uuid>/` 目录迁移到新 ID 格式,撞名挂 `_legacy`
后缀;迁移结果在 banner 打印一行。

### 续接异常处理

`/resume` / `--resume` 内部走四件套,坏数据不会让 TUI 挂掉:
- 坏行(JSON 解析失败)→ 跳过,继续加载后续行
- orphan `tool_call`(没配上 `tool_result`)→ 截断到 call 之前
- token 超限 → 调一次 `maybe_compact` 压一压
- 距上次会话 > `time_gap_threshold_hours`(默认 8 小时)→ 插一条
  `<system-reminder type="time_gap">` 提醒 LLM 上下文可能已变

### FAQ

**Q:关掉 sessions 会怎样?**
A:`config.sessions.enabled = false` → `SessionArchiver` 不构造,JSONL 不
写,`/resume` 显示"没有可恢复的 session"。等同 v0.7 行为。

**Q:`/clear` 会不会删掉 JSONL?**
A:不会。`/clear` 只清空内存里的 conversation,JSONL 文件保留,仍可用
`/resume` 找回来。

**Q:30 天前的会话还能 `/resume` 吗?**
A:不能。启动时 `cleanup_expired` 把超期 JSONL + 对应 context 目录删掉。

**Q:重命名 session_id 后,旧 uuid 还在磁盘上吗?**
A:升级时被迁移,新 ID 是 v0.8 格式。磁盘上不会同时存在两个目录。

## 四、自动记忆(双层笔记)

v0.7 用单一 `memory_path` 文件(整个塞进 system prompt)。v0.8 拆成
**用户级**和**项目级**两层目录,每条笔记一个独立 Markdown 文件,另有一份
`MEMORY.md` 索引(200 行 / 25KB 上限)。

### 默认配置

```yaml
memory:
  enabled: true
  user_dir: ~/.config/baozicode/memory/user        # 跟人走
  project_dir: .baozicode/memory                    # 跟项目走
```

### 笔记四类 + 自动路由

| 类型 | 路由 | 典型例子 |
|------|------|----------|
| `user-pref` | user_dir | "用户偏好中文" |
| `correction` | user_dir | "用户纠正:不要用 `os.path`,改 `pathlib`" |
| `project` | project_dir | "项目用 Pydantic v2" |
| `reference` | project_dir | "API 文档:https://..." |

### 工作机制

Agent 自然停下(模型最终回复无工具调用)→ **异步**调 LLM 抽取当前对话
的笔记 → 按类型路由到对应目录 → 更新 `MEMORY.md` 索引。下次启动时
`PromptBuilder` 把两层索引一起灌进 `stable_system` 段,Agent 看到时已
"读过"。

### 索引上限

`MEMORY.md` 控制在 **200 行 / 25KB**(约 2-3K tokens):
- 正常增长 → 不动
- 接近上限 → 警告(`WARN`)
- 触发上限 → 自动调 LLM 合并相似笔记(回 `NORMAL`)
- 自动合并失败 / 连续触发 → `HUMAN_NEEDED`,提示用户人工处理

### FAQ

**Q:旧 `memory_path` 文件怎么办?**
A:v0.8 兼容 —— 当 `memory_path` 指向的文件存在 + 两个新层目录都为空
时,banner 打印一行 `WARN: memory_path is deprecated, ...` 然后 fallback
把单文件当 user 级索引读。v0.9 彻底切干净。**建议手动迁移**:

```bash
# 旧 memory.md → 新双层
mv ~/.config/baozicode/memory.md ~/.config/baozicode/memory/user/MEMORY.md
```

**Q:关掉 memory 会怎样?**
A:`config.memory.enabled = false` → memory bootstrap 跳过,索引不灌
system prompt,自动更新不跑。`/memory` 命令显示"disabled"。

**Q:删除笔记后 `MEMORY.md` 怎么更新?**
A:LLM 在每轮更新时被告知当前索引,会主动 rewrite。手工删文件后索引
会"幽灵"指向不存在的 slug —— 下次自动更新会被 LLM 清理。

**Q:跨 session 删除别人写的笔记?**
A:不允许。`delete` 操作要求 `source_session` 匹配,跨 session 直接
被 `MemoryUpdater` 拒绝(防止不同 session 互踩)。`update` 允许跨 session
追加 / 合并。

## 五、CHANGELOG 摘要

**新增能力**
- 三层 `BaoZiCode.md` 加载 + `@include`(深度限 + 环路 / 路径拦截)
- JSONL 会话存档 + 自动清理过期
- 双层长期记忆 + 自动 LLM 笔记抽取
- `time_gap` reminder(默认 8h 间隔)
- CLI `--resume` / `--new` / `--no-banner`
- Slash `/resume` / `/memory` / `/new`

**修改能力**
- `session_id` 格式从 uuid4 32 字符 → YYYYMMDD-HHMMSS-xxxx 20 字符
- 启动顺序调整:permissions → instructions → memory → sessions
- 启动 banner 增三行摘要(指令 / 记忆 / 会话)

**废弃字段**
- `AppConfig.memory_path` —— v0.9 移除,改用 `memory.user_dir` +
  `memory.project_dir`

## 六、最小迁移动作清单

1. **不动配置也能跑** —— v0.8 默认值与 v0.7 兼容,旧 config.yaml 不改也行
2. **(建议)创建 `BaoZiCode.md`** —— 在项目根或 `~/.config/baozicode/`
   写一份项目 / 个人指令
3. **(可选)关掉不需要的层** —— `memory.enabled: false` 或
   `sessions.enabled: false` 退回 v0.7 行为
4. **(可选)迁移旧 memory.md** —— 按上面 §四 末尾的 bash 一行迁移

升级完成后,启动 banner 会显示:
```
[BaoZiCode] 指令: N layers loaded (...)
[BaoZiCode] 记忆: X notes (user: A, project: B), index: L lines / B bytes
[BaoZiCode] 会话: M sessions found, latest: <id> (<title>)
```

看到这四行说明 v0.8 三层都正常起来了。
