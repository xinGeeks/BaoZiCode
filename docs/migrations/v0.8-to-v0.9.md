# v0.8 → v0.9 迁移指南

v0.9 重写 slash 命令:从 `tui/chat_screen.py` 里的 16 命令 if/elif 树 → 一等公民
模块 `baozicode/commands/`(注册中心 + dispatcher + 实时补全 + narrow context)。
升级会带来一个 **breaking change**:6 个旧命令被删除,需要替换;2 个命令
(`/resume /new`)合并入 `/session`。

---

## 一、发生了什么变化

| 维度 | v0.8 | v0.9 |
|------|------|------|
| Slash 命令数 | 16 个(硬编码 if/elif) | **10 个**(可扩展 registry) |
| 命令元数据 | 散落在 4 个文件 | 集中在 `commands/builtin.py` |
| Alias 冲突检测 | runtime(直到用户输入才报错) | **boot 时 panic** |
| Case sensitivity | case-sensitive | **case-insensitive** |
| Tab 补全 | 无 | **实时补全**(每次按键) |
| 命令实现位置 | chat_screen 私有方法 | `commands/` 包 + ChatScreen 注入 |
| 单元测试 | 必须 mount Textual app | stub CommandContext |
| 状态栏 mode | `mode=plan / mode=full` + `perm_mode=default` | `[DEFAULT] / [PLAN] / [STRICT] / ...` |

## 二、命令迁移表

### 2.1 删除的 6 个旧命令

| 旧命令 | 替代方案 | 备注 |
|--------|----------|------|
| `/exit` | `Ctrl+C` | App `BINDINGS` 已有,退出行为不变 |
| `/model` | 改 `config.yaml` 重启 | banner 写明当前后端 + model |
| `/tools` | 合并入 `/status` 输出 | `/status` 现在列可用工具摘要 |
| `/mcp` | 启动时 stderr banner | 启动 banner 写明 MCP server 状态;不再单独命令 |
| `/stop` | `Ctrl+C` | 运行中 `Ctrl+C` + v0.7 agent cancel hook |
| `/auto` | `/permission mode permissive` | L5 modal 内部行为不变(本会话跳过所有 Modal) |

### 2.2 合并的 2 个命令 → `/session`

| 旧命令 | 替代方案 |
|--------|----------|
| `/resume` | `/session` 弹窗选项里"恢复某 session" |
| `/new` | `/session` 弹窗选项里"开新 session" |

`/session` 无 args,弹出现有 `StartupSessionScreen`,
选项:`恢复某 sid` / `开新` / `保持当前(取消)`。

### 2.3 改名的 1 个命令

| 旧命令 | 新命令 |
|--------|--------|
| `/permissions` | `/permission` (主名)+ `/permissions` (别名) |

`/permissions` 仍然可用(alias),但 `tab` 补全 + `/help` 列表里只显示主名。
完整 `permissions` 字符串是兼容写,功能完全一致。

### 2.4 严格动词化的 2 个命令

| 命令 | v0.8 | v0.9 |
|------|------|------|
| `/plan foo bar` | 进入 plan mode 并跑任务 `foo bar` | **仅切 plan_mode=True**,args 静默忽略 |
| `/do foo bar` | 退出 plan mode 并跑任务 `foo bar` | **仅切 plan_mode=False**,args 静默忽略 |

**这是 breaking change**——`/plan foo` 的旧习惯("一进入 plan mode 立即让 Agent 分析 foo")
不再成立。新流程:
1. `/plan` (切模式)
2. 用户单独发消息 `请分析 X`(走 Agent 时仍受 plan_mode=read-only tools 约束)

`/do` 同理。

## 三、新命令一览(10)

| 命令 | 类型 | 说明 |
|------|------|------|
| `/help` | LOCAL | 列 10 个内置命令,描述 + usage |
| `/compact` | UI_STATE | 手动压缩上下文(Layer 1 + Layer 2)|
| `/clear` | UI_STATE | 清空当前对话 + 索引 + session_usage |
| `/plan` | UI_STATE | 切 plan_mode=True,args 静默忽略 |
| `/do` | UI_STATE | 切 plan_mode=False,args 静默忽略 |
| `/session` | UI_STATE | 弹 StartupSessionScreen 选恢复 / 开新 |
| `/memory` | LOCAL | 显示 user / project 两层记忆状态 |
| `/permission [mode]` | UI_STATE | 切 strict/default/permissive;无 args 显示当前 |
| `/status` | LOCAL | 显示 mode + 后端 + token 累计 + memory 摘要 |
| `/review [<since>]` | PROMPT | 让 Agent 审查自 {since} 起的改动 |

## 四、配置新增

```yaml
# config.yaml v0.9 新增块
commands:
  review_prompt: "自定义审查prompt:{since}|SUFFIX"  # 可选 override
```

- 不设置(`null`) → 用 builtin 默认文本
- 模板字符串 `{since}` 是必带占位符,运行时被 `/review <since>` 的 args 替换;
  若 `/review` 无 args,默认替换为 `"本次会话开始"`
- 默认文本:`"请审查当前会话自 {since} 以来的所有改动(patch、命令输出、对话)。\n输出三段:## 摘要 / ## 风险点 / ## 建议修复。"`

## 五、最少动作升级

1. **什么都不改直接升级**:`pip install baozicode==0.9.0`,10 命令正常工作
2. **肌肉记忆迁移**:
   - `/exit` → `Ctrl+C`
   - `/model` → `vim config.yaml` + 重启
   - `/tools /mcp` → 启动时 banner 摘要已够,需要详细时看 `/status`
   - `/stop` → 运行中 `Ctrl+C`
   - `/auto` → `/permission mode permissive`
   - `/resume /new` → `/session` 弹窗
3. **可选**:在 `config.yaml` 设置 `commands.review_prompt` 覆盖默认 review 模板

## FAQ

**Q: 为什么删 `/auto`?**  
A: v0.5 L5 权限 modal 的"自动模式"概念对用户来说不够透明——`/auto` 一开
用户不知道后面发生了什么。改用 `/permission mode permissive` 后,用户主动选
一个语义清晰的 mode,且该 mode 在 `/status` 里直接显示。

**Q: `/plan foo` 旧版本会跑任务,新版为什么不跑了?**  
A: v0.6 设计 `/plan [task]` 是为了"一进入 mode 立即让 Agent 分析"。这混淆了
模式切换和任务触发两件事。v0.9 拆分:模式切换靠 `/plan` 动词,任务靠单独消息。
这样 `plan_mode=True` 后,任何用户发起的消息都走只读 Agent,行为统一可预测。

**Q: 怎么加自定义 slash 命令?**  
A: v0.9 起 `CommandRegistry` 是公开 API。可以在用户脚本里:
```python
from baozicode.commands.registry import CommandRegistry, CommandDef, CommandType, LocalResult

reg = CommandRegistry()
async def my_handler(args, ctx):
    ctx.show_info(f"hi {args}")
    return LocalResult()
reg.register(CommandDef(
    name="hello", description="say hi", usage="/hello <name>",
    type=CommandType.LOCAL, handler=my_handler,
))
reg.freeze()
```
但当前 App 的 registry 是 `BaoZiCodeApp._command_registry`,私有不暴露;
v0.10 计划支持 user-level 自定义 hook。

**Q: Tab 补全的 popover UI 何时落地?**  
A: v0.9 简化 UX:`on_input_changed` 钩子在 `completor.candidates()` 上跑,
但弹菜单 UI(OptionList)留到 v0.10。当前用 placeholder 提示 + 单匹配自动补全。
