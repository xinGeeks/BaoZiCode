# v0.9 → v1.0 迁移指南

v1.0 是 v0.9 之上的**新能力层**:Skill 系统。把可复用的 AI 操作封装成独立 Markdown
文件,模型按需加载而不是把 SOP 全部塞进 system prompt。**无 breaking change** —
v0.9 旧配置 / 旧 slash 命令 / 旧 skills_dir 全部继续工作。

---

## 一、发生了什么变化

| 维度 | v0.9 | v1.0 |
|------|------|------|
| 可复用 SOP | 写在 slash 命令 / system prompt | 独立 Markdown 文件 + frontmatter |
| 加载方式 | 全部启动时塞进 system prompt | 两阶段:启动只见名字,按需调 `load_skill` 工具 |
| 工具选择 | 7 工具全部暴露给模型 | 激活 Skill 后白名单收窄到 union |
| Slash 命令 | 11 个 | **12 个**(新增 `/skill`) |
| 上下文位置 | system prompt 段(env_info) | 同位置 + 新 `<system-reminder type="active_skills">` 块 |
| Prompt 段名 | `## 已激活 Skill`(v0.4 旧路径) | `## 可用 Skill(两阶段加载)` |

## 二、Skill 文件格式

### 2.1 目录与命名

- 目录形 Skill(推荐):`<skills_dir>/<skill-name>/SKILL.md`
  - `<skill-name>` 必须是 `^[a-z][a-z0-9-]*$`(小写字母开头,可含数字和连字符)
  - 整目录可作为"能力包"分发:除 SKILL.md 外,模板/示例/辅助脚本/参考文档都打包在内
  - SKILL.md 是入口,正文里可用相对路径引用其它文件(`./examples/case1.md` 等)

- 单文件 Skill(简单场景,向 v0.4 兼容):`<skills_dir>/<skill-name>.md`
  - 仅在 v0.4 fallback 路径生效(`skill_registry=None` 时)
  - v1.0 正常路径推荐目录形

### 2.2 frontmatter 字段

| 字段 | 必填 | 类型 | 默认 | 说明 |
|------|------|------|------|------|
| `name` | ✅ | string | — | 唯一标识,符合 `^[a-z][a-z0-9-]*$` |
| `description` | ✅ | string | — | 一句话说明,启动时塞进 system prompt |
| `mode` | | `shared` \| `independent` | `shared` | 执行模式 |
| `allowed-tools` | | list[string] | `[]`(全允许) | 白名单,启动期 L1 校验存在性 |
| `history-bubbles` | | int ≥ 0 | 0 | 独立模式带几条历史气泡进子对话 |
| `model` | | string | (主后端) | 独立模式指定子对话用的模型 |
| `hidden` | | bool | false | true → 不进 prompt section,但仍可手动 load |

### 2.3 正文(Markdown body)

- 发给模型的 SOP 指令,激活后整段钉在 `<system-reminder type="active_skills">` 里
- 支持参数占位符替换:
  - `{var}` — 必带参数,无 args 报错
  - `{var:default}` — 可选参数,无 args 用 default
- 激活时调用 `load_skill(name, args={"var": "value"})`,body 渲染后塞入 reminder

### 2.4 完整示例

```markdown
---
name: audit
description: 审查某 area 的代码改动并出报告
mode: independent
allowed-tools: [Bash, Read, Grep]
history-bubbles: 2
---

审查 `{area}` 范围自 `{since:HEAD~10}` 以来的所有代码改动,生成三段报告:
`## 摘要` / `## 风险点` / `## 建议修复`。

## SOP
1. 调 `Bash` 跑 `git log --since="{since}" --oneline -- {area}` 看涉及 commit
2. 调 `Bash` 跑 `git diff <base>..HEAD -- {area}` 看文件级改动
3. 对每个改动文件,选 1-3 个关键 hunk 调 `Read` 看完整内容
4. 调 `Grep` 在改动文件里搜 TODO / FIXME / XXX / HACK 标记
5. 归纳 3 段报告
6. 摘要回流到主对话

## 模板
- **## 摘要**:改动主题 + 涉及文件 + 关键模块
- **## 风险点**:并发 / 边界 / 错误处理 / 性能 / 安全 五个维度逐项
- **## 建议修复**:按优先级 P0/P1/P2 排
```

激活:`/skill audit area=src/auth since=2026-07-01` 或 LLM 调
`load_skill(name="audit", args={"area": "src/auth", "since": "2026-07-01"})`。

## 三、激活流程

### 3.1 启动时(自动)

```
┌──────────────────────────────────────────────────────────────┐
│ 1. bootstrap_skills()                                        │
│    - 扫 builtin + user + project 三级目录                     │
│    - 解析 SKILL.md frontmatter(失败文件跳过,继续)              │
│    - L1 校验:allowed-tools 全部存在(否则 SystemExit)          │
│    - 构造 SkillRegistry / SkillActivation / SkillLoader      │
│ 2. 系统 prompt 注入:                                          │
│    `## 可用 Skill(两阶段加载)` 段(name + description + 来源)  │
│ 3. /clear 时同步清空 activation                               │
└──────────────────────────────────────────────────────────────┘
```

### 3.2 激活时(LLM 触发 / 用户触发)

```
/skill <name> [args...]
        │
        ▼
load_skill(name, args) 工具
        │
        ├─ args 替换 {var} / {var:default} 占位符
        ├─ body 钉入 SkillActivation
        ├─ 注册为 slash 短命令(同 name)
        └─ 返回 body 内容(给 LLM 看到完整 SOP)
        │
        ▼
下一轮 Agent 重建 prompt:
  <system-reminder type="active_skills">
    ## /skill commit
    <body 渲染结果>
    ## /skill review --since=...
    <body 渲染结果>
  </system-reminder>
```

### 3.3 两种执行模式

| 模式 | 行为 | 适用场景 |
|------|------|----------|
| `shared` | Skill body 注入主对话 reminder,工具在主对话内执行 | 短任务、与当前上下文紧密耦合的 SOP |
| `independent` | SkillLoader 调独立 runner(supports `args` + `history-bubbles`);子对话跑完后摘要回流主对话 | 长任务、需要隔离上下文的分析(审查 / 测试) |

`history-bubbles=N` 把主对话最近 N 条消息一起送进子对话,默认 0(隔离)。

## 四、配置新增

```yaml
# config.yaml v1.0 新增块(可省略)
skills:
  enabled: true                   # 整系统开关(默认 true)
  builtin_dir: <pkg>/skills/builtin  # 默认,通常不动
  user_dir: ~/.config/baozicode/skills
  project_dir: ./.baozicode/skills
  # summary_model: claude-sonnet-4-6  # v1.1 计划
  # history_bubbles_default: 0         # v1.1 计划
```

- 整块省略 → 全走默认
- `enabled: false` → 整套系统空集,prompt section 也不出现「可用 Skill」段
- 显式 `user_dir` / `project_dir` 覆盖默认(项目级优先于用户级)
- 启动期允许加载 builtin Skill 才会写到 `prompt/section/skills.py`;
  `enabled: false` 同时跳过 `load_skill` 工具注册

## 五、Slash 命令新增

| 命令 | 类型 | 说明 |
|------|------|------|
| `/skill list` | LOCAL | 列出可见 Skill(name + description + 来源) |
| `/skill <name> [args...]` | UI_STATE | 加载并激活 Skill;args 形如 `key=value` 或 `key=value with spaces` |
| `/skill clear` | UI_STATE | 清空所有已激活 Skill(不动 Skill 文件) |

`/skill <name>` 加载后,会**自动**注册同名 slash 短命令(目前激活是单向的:
已注册的 short command 等价于 `/skill <name>`,完整命令集见 `/help`)。

## 六、热更新 / 编辑流

1. 修改 `<skills_dir>/<skill-name>/SKILL.md`(body 或 frontmatter)
2. 调 `app.skills.registry.reload("<skill-name>")` 立即拿到新 SkillDef
3. 已激活的 activation 不动 — 下次新激活会用新内容,旧激活的 body 仍按旧版渲染
   (要全量刷新:先 `/skill clear` 再重新 load)

CLI / 外部脚本想热更新:在 Python REPL 里调
```python
from baozicode.app import BaoZiCodeApp
app.skills.registry.reload("commit")
```

## 七、最少动作升级

1. **什么都不改直接升级**:`pip install baozicode==1.0.0`,v0.9 行为完全保留
2. **体验新能力**:启动后看 banner 多一行 `[Skill] X 个可用`,prompt 里出现
   `## 可用 Skill(两阶段加载)` 段。直接 `/skill commit` 试一下
3. **加自己的 Skill**:
   - 用户级:`mkdir -p ~/.config/baozicode/skills/<my-skill>/`,写 SKILL.md
   - 项目级:`mkdir -p ./.baozicode/skills/<my-skill>/`,写 SKILL.md
   - 重启或 `app.skills.registry.reload("<my-skill>")`
4. **完全不用 Skill 系统**:`skills.enabled: false` 一行就关掉,回到 v0.9 行为

## 八、迁移常见问题

**Q: v0.4 老 `skills_dir/*.md` 单文件 Skill 还能用吗?**  
A: 能。`prompt/sections/skills.py` 在 `skill_registry=None` 时退回 v0.4 旧路径,
扫 `skills_dir/*.md` 并用 `## 已激活 Skill` 标题。v1.0 正常路径不识别老单文件
格式(只认目录形 `<name>/SKILL.md`),但 v0.4 路径保留以保持后向兼容。

**Q: 旧 `prompt` 里的 "已激活 Skill" 段会消失吗?**  
A: v1.0 默认注入的是新 `## 可用 Skill(两阶段加载)` 段(列所有可见 Skill 的
name + description)。`## 已激活 Skill` 段(具体 body)只在以下情况出现:
- LLM 调了 `load_skill` 把 Skill 激活,或者
- 走 v0.4 fallback 路径(skill_registry=None)

**Q: Skill 声明的 `allowed-tools` 写错了(比如不存在的工具)怎么办?**  
A: 启动期 L1 校验就会 `SystemExit`,在 banner 阶段就拦住。日志里写明
`<path>: frontmatter 校验失败: allowed-tools: <name> 不在工具白名单`。
修对才能启动。

**Q: 我能关掉某个内置 Skill 吗?**  
A: v1.0 不提供 disable 单个 Skill 的开关。两种"去掉"方式:
- 用户级 `~/.config/baozicode/skills/<name>/SKILL.md` 覆盖(同名高优先级,
  内容可以空,只剩 frontmatter)
- 项目级 `enabled: false` 关整套(没有这个选项,但可以删 builtin 目录文件 —
  不推荐,会随升级恢复)

**Q: 多个 Skill 的白名单怎么合并?**  
A: 取 **union**。任何激活 Skill 允许的工具都能调,所有激活 Skill 都不允许
的工具被拒。`load_skill` 自身是 system 工具,**永远**放行,不受白名单约束。

**Q: 独立模式 Skill 的子对话怎么实现?**  
A: `SkillExecutor` 持有一个 `independent_runner: Callable[[SkillDef, args], Awaitable[str]]`,
默认实现委派给 `executor.execute`(stub);生产代码由 `BaoZiCodeApp` 在运行时
注入真实 runner,通常是开新 `Agent`(独立 system + conversation),完成后把
最后一条 text 摘要回流。详细 runner 注入代码见 `baozicode/app.py:_setup_skill_runner`。

**Q: 怎么写测试覆盖我的 Skill?**  
A: `tests/skills/test_skill_builtin.py` 和 `tests/integration/test_v10_skills_e2e.py`
是参考样例。关键测试点:
- 启动 → registry 看到 Skill(检查 `app.skills.registry.lookup("my-skill")`)
- 激活 → `loader.load_skill("my-skill", args={...})` 返回 ok
- 占位符替换 → `activation.render_active_section()` 含替换后的 body
- 白名单 → `build_skill_filter(reg).is_allowed(ToolCall(name="X"))` 行为符合预期
- L1 校验 → 故意写一个不存在的 `allowed-tools` 测试 `SystemExit`
