# v1.2 → v1.3 迁移指南:Worktree 隔离

v1.3 在 v1.2 之上加一层 **git worktree 隔离**,让带
`isolation: worktree` 的 sub-Agent 在独立的工作目录里跑,主 Agent 与
其他 sub-Agent 不会被它的文件改动打扰。本指南覆盖:

- 新增的 frontmatter 字段 + agent 配置开关
- Bash `cwd` 参数(向后兼容)
- cache 行为变化(主 Agent 命中 vs worktree sub-Agent 不命中)
- 一段完整可跑通的 phase1/api-designer 示例

## 启用 worktree

默认**不启用**(零行为变化)。要启用,在 `config.yaml` 加:

```yaml
subagents:
  worktree:
    enabled: true
    link_paths: [.venv, node_modules, .cargo]
    copy_paths:
      - .baozicode/BaoZiCode.md
      - .env
    max_concurrent: 5
    retention_minutes: 30
    daemon_interval_seconds: 60
```

`project_root` **必须是 git repo**(WorktreeManager 构造时校验,否则
banner warning 静默不启用)。Worktree 目录固定在
`<project>/.worktrees/<name>/`,自动加到 `.gitignore`。

## role frontmatter 声明

```yaml
---
name: api-designer
description: 设计后端 API 契约
isolation: worktree
allowed-tools: [Read, Grep, Glob, Write, Edit]
---
你是 API 设计师,工作流如下...
```

- `isolation: worktree` → sub-Agent 在 `.worktrees/api-designer/` 跑
- 不写 `isolation`(或显式 `null`)→ 走 v1.2 老路径(共享主 project_root)
- 嵌套命名支持:`isolation: worktree` + role 名 `phase1/api-designer`
  → worktree 在 `.worktrees/phase1/api-designer/`

## Bash `cwd` 参数(向后兼容)

v1.3 给 Bash 工具加了 `cwd` optional 参数:

- **不传 `cwd`** → 走 v1.2 老路径(`plan_cd` + commit session.cwd,
  完全等价)
- **传 `cwd=<abs-path>`** → 在该目录跑,执行完**不**更 session.cwd
  (fire-and-forget)。worktree sub-Agent 由 SubAgentManager 注入,
  LLM 不直接传。

```json
{
  "command": "cat README.md",
  "cwd": "/repo/.worktrees/api-designer"
}
```

非法 `cwd`(相对路径 / 不存在 / 不是目录 / 在所有有效 root 外)→ reject
不执行。

## cache 行为变化

- **主 Agent**:BuiltPrompt.byte-identical → Anthropic cache 命中,
  行为零变化
- **worktree sub-Agent**:`env_info.cwd` 段因 worktree 路径不同 →
  byte-identical 性被打破 → cache miss(每个 worktree sub-Agent 首
  次 LLM 请求都未命中)

这是设计取舍:不引入第二份缓存,sub-Agent 复用主 Agent 的 prompt
template,只改 cwd 占位符。

## 退出决策

worktree sub-Agent 跑完:

- `done` / `failed` → `WorktreeManager.exit(force=False)`
  - 全干净 → 删除
  - 有未提交修改 / 未推送 commit → 保留 detached 状态,TUI 卡片
    显示 `worktree: detached`
- `canceled` → `force=True` → 删除

`CleanupDaemon` 后台跑(默认 60s 一次)扫「长时间未动 + 没活跃 task
+ 全干净」的 worktree 强制清掉。三层过滤:**task 活跃 → 时间 →
干净度**,任意一层不过就 skip。

## 完整 phase1/api-designer 示例

```yaml
# .baozicode/agents/phase1/api-designer/AGENT.md
---
name: phase1/api-designer
description: 设计阶段 1 的后端 API 契约
isolation: worktree
allowed-tools: [Read, Grep, Glob, Write, Edit]
---
你负责 phase1 的 API 契约设计:
- 在 `<repo>/.worktrees/phase1/api-designer/` 工作
- 读 `requirements.md`,输出 `openapi.yaml` + `interfaces.ts`
```

```yaml
# config.yaml
subagents:
  worktree:
    enabled: true
    max_concurrent: 3
```

主 Agent 派活:

```text
> 用 phase1/api-designer 设计 phase1 API
```

SubAgentManager 派发:

1. 校验 `phase1/api-designer` 在 registry
2. spawn → SubAgentRuntime 看到 `isolation: worktree` → 调
   `WorktreeManager.create("phase1/api-designer")`
3. Initializer 跑 4 步:链接 `.venv`、复制 `.env`、设
   `core.hooksPath=../_hooks/`、追加 `.worktrees/` 到 `.gitignore`
4. Agent 在 `.worktrees/phase1/api-designer/` 跑,所有 Bash 调用自动
   带 `cwd=<worktree_path>`
5. 完事 → `exit` 决策 → 删 worktree 或留 detached

## 故障排查

| 现象 | 原因 | 解决 |
|------|------|------|
| `role 'xxx' 声明 isolation=worktree, 但 SubAgentRuntime 未注入 WorktreeManager` | 没启用 worktree 或 project_root 非 git | 配 `subagents.worktree.enabled=true` + 项目根是 git repo |
| `fork mode + isolation=worktree 互斥` | 用 fork 模式派 worktree role | fork 强制走主 repo;worktree 角色必须 definition 模式 |
| TUI 卡片显示 `worktree: detached` | sub-Agent 留了未提交 / 未推送改动 | 用 `git worktree list` 查路径,手动 review / commit / 删 |
| App 退出后 `.worktrees/` 残留 | on_unmount 异常中断 | 重启时 daemon 自动清理(stale + clean) |
