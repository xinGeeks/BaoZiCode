# v1.3 → v1.4 迁移指南:Team Foundation

v1.4 是分 4 个独立 proposal 推进的大版本。本文档只覆盖
**v1-4-team-foundation** — Team 数据层 + Mailbox + Lockfile + CLI。
后续 3 个 proposal 在此之上扩展:

- **v1-4-team-tools** — `team_dispatch` / `team_send_message` /
  `team_cancel` / `team_merge` 协作工具(Foundation 阶段**没有**这些工具)
- **v1-4-team-pane-backend** — tmux / iTerm2 / Windows Terminal pane 后端
- **v1-4-team-coordinator** — 双锁开关(配置 + 环境变量)+ 剥夺写工具

**无 breaking change**。v1.3 项目升级 v1.4 后:

- 主对话照常跑(`baozicode` / `baozicode --resume` / `--new`)
- 旧的 SubAgent / Worktree / Hooks / Skills / Memory / Sessions 全不动
- 新增 `baozicode team <action>` CLI 子命令(可选,不影响老路径)
- 新增 `teams:` 配置块(可选,省略走默认)

## 启用 Team 系统

Foundation 阶段**默认全开**(`teams.enabled = true`),无需配置。要禁用
(整套 Team 子命令关掉),在 `config.yaml` 加:

```yaml
teams:
  enabled: false
  dir: ~/.config/baozicode/teams/   # 可选,默认就是这个
```

`teams.dir` 支持 `~` 展开,所有 team 的持久化文件都放这里。

## 新 CLI 子命令

```bash
# 建 team
baozicode team create devops --lead alice
# 列 team
baozicode team list
# 看 team 详情(pretty JSON)
baozicode team show devops
# 激活 team(Foundation 阶段仅打印,完整 dispatch 见 v1-4-team-tools)
baozicode team use devops
# 删 team(默认交互式确认,--yes 跳过,--force 容错目录不在)
baozicode team destroy devops --yes
```

退出码:

| 码 | 含义                                       |
|----|--------------------------------------------|
| 0  | 成功                                       |
| 1  | 通用错误(用户拒删 / 参数解析失败)        |
| 2  | team 名不合法(`TeamNameTooShort` 等)      |
| 3  | team / member 不存在(`TeamNotFound` 等)   |
| 4  | 权限 / IO 错(`PermissionError` / `OSError`)|
| 5  | 配置错误(`ConfigError`)                   |

## 文件布局

```
~/.config/baozicode/teams/
└── <team-name>/
    ├── team.json           # Team dataclass 持久化
    └── <member-name>/
        ├── inbox.jsonl     # 收件箱(收 Lead / 其他 member 的消息)
        ├── outbox.jsonl    # 发件箱
        ├── state.json      # 运行时状态(status / last_active_ts / ...)
        ├── wake.signal     # 唤醒信号(空文件,mtime 变化触发 wait_for_wake)
        └── .lock           # mailbox 锁文件(cross-platform fcntl/msvcrt)
```

## 5 个后端枚举

`Member.backend` 是 Pydantic Literal,5 种:

| 值                       | 含义                                                                  |
|--------------------------|-----------------------------------------------------------------------|
| `pane-tmux`              | tmux pane 内跑完整实例(Foundation 占位,pane backend 在后续 proposal)|
| `pane-iterm2`            | iTerm2 pane 内跑(同上)                                              |
| `pane-windows-terminal`  | Windows Terminal pane 内跑(同上)                                    |
| `coroutine`              | 同进程 asyncio 协程轻量跑(Foundation 默认)                          |
| `worktree-coroutine`     | 协程 + git worktree 隔离(后续 proposal 接通)                        |

LLM 拼错(如 `pane-Tmux`)启动期 fail-fast。

## Python API 摘要

```python
from baozicode.teams import (
    Team, Member, Message, Mailbox, TeamsRegistry, TeamStore,
    TeamNameValidator, mailbox_lock,
    BackendType, MemberState, default_member_state, fill_message_timestamp,
    TeamNameInvalid, TeamAlreadyExists, TeamNotFound,
    MemberAlreadyExists, MemberNotFound,
)

# 名字校验(纯函数)
TeamNameValidator.validate("devops")  # 通过
TeamNameValidator.validate("DevOps")  # 抛 TeamNameBadChar

# Registry(全局索引)
reg = TeamsRegistry.bootstrap(config)  # 或 TeamsRegistry(teams_dir)
teams = reg.list_teams()               # 字典序
store = reg.get("devops")              # TeamStore | None
new_store = reg.create_team("devops", lead="alice")
reg.delete_team("devops", confirm=True)

# TeamStore(单 team 目录操作)
store = TeamStore.from_name(teams_dir, "devops")
team = store.show()
store.add_member(Member(name="alice", role="backend"))
store.get_member("alice")
store.destroy(confirm=True)

# Mailbox(member 邮箱文件层)
Mailbox.append_message(member_dir, "inbox", Message(sender="lead", body="hi"))
Mailbox.read_messages(member_dir, "inbox")
Mailbox.read_state(member_dir)         # → MemberState (default offline)
Mailbox.write_state(member_dir, MemberState(status="idle"))
Mailbox.touch_wake(member_dir)
await Mailbox.wait_for_wake(member_dir, timeout=30.0)

# 锁
with mailbox_lock(member_dir / ".lock"):
    # critical section
    ...
```

## 跨平台锁协议

`mailbox_lock` 在 POSIX 用 `fcntl.flock`(advisory,在 Linux/macOS 测试),
Windows 用 `msvcrt.locking`(mandatory)。

- 默认 `timeout=5.0s`,`stale_seconds=30.0s`
- 拿到锁后写入 `{pid}\n{hostname}\n{ts}\n` 再 `os.fsync` 落盘(便于 debug)
- 锁文件 mtime > `stale_seconds` 时下一个 caller 偷锁(steal),避免僵死

50 ms 退避重试,busy 错误覆盖 `errno=11/13/33/35/158`(POSIX `EAGAIN`/`EACCES`
/ `EDEADLK` / Windows `ERROR_LOCK_VIOLATION` 等)。

## Foundation 阶段**没做**什么

以下能力**留给后续 3 个 proposal**,Foundation 不实现:

- `team_dispatch` / `team_send_message` / `team_cancel` / `team_merge` 工具
  → v1-4-team-tools
- pane 后端实际派生 / 唤醒 tmux/iTerm2/Windows Terminal → v1-4-team-pane-backend
- coordinator 模式(剥夺写文件工具 + env var 启用) → v1-4-team-coordinator
- 跨机器分布式团队
- 成员间实时流式通信
- 复杂任务依赖约束(仅支持任务的 add/del/get/list)

`team use <name>` 在 Foundation 阶段**仅打印 "Activated team ..." 占位信息**,
完整 dispatch 见 v1-4-team-tools。

## FAQ

**Q: 老的 SubAgent / Worktree 系统会冲突吗?**

A: 不会。`baozicode/teams/` 是新模块,跟 `baozicode/agents/` / `baozicode/worktree/`
   完全独立。`Member.backend="worktree-coroutine"` 是个字面量,不直接接
   WorktreeManager(v1-4-team-pane-backend proposal 接通)。

**Q: 我能不写 `teams:` 配置块吗?**

A: 可以。省略整块时 `AppConfig.teams = None`,Foundation 走默认
   `~/.config/baozicode/teams/`,CLI 仍能工作。

**Q: 现有 v1.3 项目升级需要改 `.baozicode/` 目录吗?**

A: 不需要。v1.4 的目录结构全新,在 `~/.config/baozicode/teams/`(独立于项目目录),
   不污染项目里的 `.baozicode/`。

**Q: Mailbox JSONL 文件被损坏一半怎么办?**

A: `Mailbox.read_messages(..., skip_bad_lines=True)` 默认跳过坏行,
   保留好行;append 用 tmp file + atomic replace 写入,正常崩溃不会留半成品。
   见 `tests/test_teams_v14_mailbox.py::TestAtomicCrash`。

**Q: 团队数据怎么备份?**

A: 整个 `~/.config/baozicode/teams/` 目录 — 普通文件,任意备份工具(rsync /
   tar / git)都适用。
