# v1.4 Pane Backend → v1.4 Team Coordinator

## 概览

v1-4-team-coordinator 在 v1-4-team-foundation / tools / pane-backend 之上,
落地 **Coordinator 监督者模式** — 通过三锁门 + 写类工具剔除 + `active_role`
接线,让 Lead Agent 在多 team / 多 Lead 协作场景下「只负责指派,不动文件;
写动作由 member 完成」。

## 为什么需要 Coordinator

v1-4-team-pane-backend 落地 Lead Agent 完整 lifecycle:6 个 team_* 协作工具
+ 5 BackendType 派生 + wake/resume/state。Lead Agent 既能派活又能 `Write` /
`Edit` / `Bash` —— 在大规模派活场景下风险过大(Lead 误改文件可能覆盖
member 已完成的工作)。

Coordinator 模式限制 Lead 的写文件工具,只留观察 + 协作能力,保证
「Lead 只负责指派,不动文件;写动作由 member 完成」。

## 三锁门

启用 Coordinator 模式需要**三处都设**:

```
锁 1 — 配置层:        config.yaml → teams.coordinator.enabled: true
锁 2 — 环境变量:      $BAOZICODE_COORDINATOR ∈ {"1", "true", "yes"} (大小写不敏感)
锁 3 — team 意图:    team.json → "coordinator": true
```

任一锁缺失 → 走现有 Lead 路径(降级,不报错);`team use --coordinator`
命令行工具会显式报告「哪一锁缺失」。

### 为什么不只一个锁?

- 配置文件可能被共享 / 上 git,设错影响大 → 需要运维/用户二次确认
- 环境变量由运维控制(生产部署 / 测试环境)→ 防止误启用
- team.json 是用户对单个 team 的明确意图 → 持久化,重启后保留
- 三者全部命中 = 显式 ≥ 3 处都做了「我确实想启用 coordinator」

## 配置示例

```yaml
# config.yaml
teams:
  enabled: true
  dir: ~/.config/baozicode/teams/
  coordinator:
    enabled: true                            # 锁 1
    env_var: BAOZICODE_COORDINATOR           # 可覆盖,默认就是这个
    allowed_tools:                           # 可覆盖,默认 Read/Grep/Glob/WebFetch + 6 team_*
      - Read
      - Grep
      - Glob
      - WebFetch
      - team_dispatch
      - team_send_message
      - team_cancel
      - team_merge
      - team_task_create
      - team_task_query
```

## 激活流程

### CLI(打印模式,不入 ChatScreen)

```bash
# 三锁全命中
BAOZICODE_COORDINATOR=1 baozicode team use --coordinator devops
# 输出:Activated team 'devops' (1 members, lead=lead, mode=coordinator)

# 锁缺失 → 降级 + stderr 报告
baozicode team use --coordinator devops
# stderr: Note: coordinator 三锁未命中 (缺: env_var);降级到 Lead 模式。
# stdout: Activated team 'devops' (1 members, lead=lead, mode=lead)
```

### TUI(实际切 active_role)

CLI `team use --coordinator` 走 `_cmd_use`(打印模式)。实际 `app.use_team`
调用在 TUI 启动后 ChatScreen.on_mount 通过 `/session use` slash 命令触发。

```bash
# 在 TUI 内 /session use 触发:
/session use --coordinator devops
# 等价于:
app.use_team("devops", coordinator=True)
# → app.active_role = "coordinator"(三锁命中)
# → ChatScreen 重建 Agent:Agent(role="coordinator", tool_registry=...)
```

## 工具白名单

| role | 看到的工具 | 触发方式 |
|------|----------|---------|
| `subagent` | 7 内置(Read/Write/Edit/Bash/Grep/Glob/WebFetch)| 默认(无 team)|
| `member` | 7 内置 | v1-4-pane-backend 的 Member Agent |
| `lead` | 7 内置 + 6 个 `team_*` | `team use <name>` |
| `coordinator` | Read/Grep/Glob/WebFetch + 6 个 `team_*`(`Write`/`Edit`/`Bash` 剔除)| `team use --coordinator <name>` |

`tool_type='internal'` 的工具(`load_skill` / `task`)对所有 role 可见,
不受 Coordinator 剔除影响。

## 内部实现

### 关键代码改动

| 模块 | 改动 |
|------|------|
| `baozicode/teams/schema.py` | `Team.coordinator: bool = False` 字段 + `__post_init__` 校验 + `to_dict`/`from_dict` |
| `baozicode/teams/store.py` | `TeamStore.create(..., coordinator=False)` kwarg + `add_member` 透传 |
| `baozicode/teams/registry.py` | `TeamsRegistry.create_team(..., coordinator=False)` kwarg |
| `baozicode/config/schema.py` | 新增 `CoordinatorConfig` + `TeamsConfig.coordinator: CoordinatorConfig | None` |
| `baozicode/teams/coordinator.py`(新)| `coordinator_enabled(config, team)` + `check_coordinator_locks(config, team)` |
| `baozicode/tools/registry.py` | `get_all_tools(role='coordinator')` 显式剔除 `Write`/`Edit`/`Bash` |
| `baozicode/teams/tools.py` | 6 个 `team_*` `role_visibility` 从 `['lead']` → `['lead', 'coordinator']` |
| `baozicode/app.py` | `App.active_role` / `App.active_coordinator` 字段 + `use_team(name, *, coordinator=False)` kwarg |
| `baozicode/tui/chat_screen.py` | 重建 Agent 时读 `app.active_role` 决定 `role` kwarg |
| `baozicode/teams/cli.py` | `team use --coordinator` flag + 三锁检查 + 降级报告 |

### 不引入新过滤层

- `ToolRegistry.get_all_tools(role='coordinator')` 已存在(v1-4-team-tools)
- `Agent(role='coordinator')` keyword-only 参数已存在
- `ToolDefinition.role_visibility` 校验已含 `coordinator`
- `AGENT_ROLES` 已含 `coordinator`

唯一新加的代码点:
1. `Team.coordinator: bool` 字段
2. `TeamsConfig.coordinator: CoordinatorConfig` 字段
3. `coordinator_enabled(config, team)` 三锁判断函数
4. `App.use_team(..., coordinator=False)` 新 keyword-only 参数
5. `App.active_role` / `App.active_coordinator` 字段
6. ChatScreen 重建 Agent 时读 `active_role` 决定 role
7. `team_*` 工具 `role_visibility` 从 `['lead']` → `['lead', 'coordinator']`
8. ToolRegistry.get_all_tools 在 `role='coordinator'` 时显式剔除
   Write/Edit/Bash
9. CLI `team use --coordinator` 扩展

## 失败模式

| 场景 | 行为 |
|------|------|
| `team use --coordinator foo`,配置 disabled | 降级 Lead,stderr 报告 |
| `team use --coordinator foo`,env var 未设 | 降级 Lead,stderr 报告 |
| `team use --coordinator foo`,team.json 无 `coordinator:true` | 降级 Lead,stderr 报告 |
| 三锁全命中,LLM 调 `Write` 工具 | `ToolRegistry.get_all_tools(role='coordinator')` 不含 Write → LLM 看不到 → 不发生 |
| Coordinator 绕过白名单直接用 Bash | `get_all_tools(role='coordinator')` 不返 Bash → LLM 看不到 → 不发生 |
| 配置文件解析失败 | ConfigError → CLI exit 5 |
| `team use --coordinator ghost`(team 不存在)| stderr `TeamNotFound` → CLI exit 3 |

## 向后兼容

- `Team.coordinator` 默认 False,旧 team.json 无字段 → `from_dict` 默认
  False
- `TeamsConfig.coordinator` 默认 None,整块省略 → 视为未启用
- `use_team(name)` 不传 `coordinator` kwarg → 走现有 Lead 路径
  (active_role='lead')
- `team use <name>` 不传 `--coordinator` flag → 现有 CLI 路径
- 7 个内置工具的 `role_visibility` 仍为 None(全员可见);Coordinator
  剔除不通过 `role_visibility` 走,而是通过 `ToolRegistry.get_all_tools`
  的 `role='coordinator'` 分支显式剔除

## Out of Scope(本 proposal 不做)

- **Member 端工具白名单** — member 已在 v1.4-pane-backend 用 7 工具
  子集(role='member')收窄,coordinator 不再触动
- **审计日志** — Coordinator 操作可审计但本 proposal 不做(留 v2.0)
- **多 coordinator 协作** — 一个 active team 只有一个 coordinator
- **运行时动态切换** — `team use --coordinator` 后,切回 `team use`
  才能退出 coordinator 模式
